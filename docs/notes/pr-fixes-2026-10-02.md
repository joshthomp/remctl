# PR fixes and the 1.7.1 upgrade bug — October 2, 2026

Local follow-up to 2.2.0, covering PRs [#53](https://github.com/viticci/remctl/pull/53), [#52](https://github.com/viticci/remctl/pull/52), [#33](https://github.com/viticci/remctl/pull/33), and issue [#56](https://github.com/viticci/remctl/issues/56). The version remains 2.2.0; these changes have not been published or merged into main.

## Fixes

- **Archived list colors (#53).** Some color archives contain an NSString object instead of plain text. The old decoder returned that object, including a binary-plist reference that JSON cannot serialize. The decoder now extracts the text. Missing hex values retain their existing empty-string behavior; malformed archives retain the blue default. The contributor's commit and authorship are preserved.
- **Unwanted workspace tabs (#52).** Ordinary plugin tools advertised and returned the full workspace interface, so background agent reads could open tabs. Those tools now return data without interface metadata in plugin mode. Explicit workspace entrypoints, sidebar support, and app-only tools retain their interface. Standalone MCP clients retain their widgets. The contributor's commit and authorship are preserved.
- **Renamed iCloud accounts (#33).** The old EventKit check required the account name to contain “iCloud.” The signed host now resolves the account's stable ID and provider from macOS account records, including descendants of an Apple account. It passes that mapping through the bridge's JSON input. A known other provider cannot qualify by calling itself “iCloud.” Unavailable records retain the old fallback. This adapts Rod Christiansen's proposal to the current architecture without relying on display names or environment overrides.
- **Stock 1.7.1 upgrade refused (#56).** The old installer generated completion files by invoking each alias separately. Because the executable name changes the output, the three files have different hashes. The new installer had incorrectly expected identical files. It now recognizes the original alias hashes and retains acceptance of the identical copies accepted by earlier 2.x installers. Modified files still fail verification and remain untouched.

## Reproduction and focused checks

The issue #56 fixture originally repeated the installer mistake by copying one completion file to all three names. Generating each alias from the actual v1.7.1 sources made the upgrade test fail against 2.2.0. The same test passed after the hash correction. It also checks the older copied-file layout, refusal without an interactive terminal, and the actual confirmed upgrade. Separate cases preserve modified scripts and modified completion files.

The archived-string bug was reproduced with a binary plist: the old decoder's result failed JSON serialization, while the corrected result contained plain strings. Six cases cover plain strings, archived strings, referenced string contents, missing hex values, invalid references and types, and list JSON output.

The account tests use a temporary database with committed WAL records and compile the actual Swift classifier. They cover renamed accounts, commas and duplicate display names, case-normalized IDs, nested Apple accounts, unrelated CalDAV accounts, unavailable records, and the existing fallback. A read-only probe on this Mac confirmed that EventKit's source ID matches the Apple account's stable database ID. No Internet Account was renamed or reconfigured. Thirty uncached lookup samples had a median of 0.215 ms; the first cold sample took 29.306 ms. The mapping is cached within each command, and commands that do not resolve an account skip the lookup.

## Limits

Checks run on this Apple silicon Mac with macOS 27. They do not establish acceptance on Intel, older supported macOS versions, or physical iPhone/iPad clients. Renamed-account behavior is covered by the actual Swift classifier with synthetic names and the real account-ID mapping, without changing the user's account settings.

A fresh Claude Code agent-session check could not run because the account had reached its weekly usage limit. Its native mod tests and configured MCP transport checks passed. This Codex session exposes RemCTL through Mac Remote rather than the standalone plugin's model tools, so the no-extra-tab contract was verified through the installed plugin protocol; native acceptance covers opening, rendering, refreshing, and navigating the explicit workspace. No claim is made of a fresh native agent conversation exercising automatic tab creation.
